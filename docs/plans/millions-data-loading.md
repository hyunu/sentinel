# 수백만 건 데이터 로딩 최적화

브랜치: `perf/millions-data-loading`
시작일: 2026-11-11

## 목표

- 보드당 수백만~수천만 건의 UART 데이터에서도 차트/테이블/세션 작업이 예측 가능한 시간 안에 동작
- 원본은 append-only로 유지하고, 조회는 사전 집계(롤업/피라미드)를 우선 사용
- 한 번에 화면에 그릴 수 있는 양 이상은 조회하지 않는다

### 목표 지표 (초안)

| 항목 | 목표 |
|---|---|
| 차트 첫 화면 | < 2초 |
| 팬/줌 반응 | < 500ms |
| 데이터 표 첫 페이지 | < 300ms |
| 전체 건수 표시 | 정확값이 필요할 때만 계산 |
| 세션 규칙 분할 | 비동기 + 진행률/취소 |

## 현재 병목

1. 수집 시 샘플 1건마다 1s/10s/60s 롤업 upsert 3회 → 쓰기 증폭
2. 스펙트럼이 원본 전체를 `$group` 스캔
3. 차트 조회마다 `CountDocuments`로 롤업 해상도 결정
4. 테이블 `include_total`의 정확한 count
5. 세션 규칙 분할이 전체 원본 스캔 + 파싱 (동기 API)
6. `session_id`, `parse_status` 인덱스 부재
7. JSON 객체 배열 응답 (전송량/파싱 비용)

## 대형 샘플 검증 (2026-11-12)

전용 보드 `PERF`(STN-PERF)에 합성 데이터 450,000행을 적재했다.

- 구성: 100,000행 → 10시간 공백 → 200,000행 → 10시간 공백 → 150,000행
- 간격: 10ms, 프레임: 7바이트 (`AA 07 10 seq value`)
- 전체 기간: 약 21.25시간, 데이터 존재 비율 6.3%, 빈 구간 2개(19h 54m)

측정 결과:

| 항목 | 결과 |
|---|---|
| 적재 | 450,000행 / 5.4분 (약 1,390행/초) |
| 총 건수 (정확 count) | 0.22s |
| 표 100행 | 0.15s |
| 표 5,000행 | 0.55s |
| 스펙트럼 raw | 0.73s |
| 스펙트럼 presence | 0.11s |
| 차트 전체(1필드) | 0.11s / 78포인트 |
| 차트 최근 1시간(150,000행) | 0.14s / 151포인트 |
| 세션 분할(450,000행) | 31.9s (비동기, 76세션/450,000행) |

- 스펙트럼에서 3개 데이터 구간과 2개 공백이 정확히 구분됨
- 비동기 분할 진행률/취소 동작 확인
- 샘플 보드/프로필은 검증용으로 유지 (`PERF value`)

### 줌·이동 반응성 (450,000행)

- 휠 줌 / 툴바 줌 모두 동작
- 줌 후 상세 조회: **62~93ms** (약 1,000포인트)
- 팬 rAF 측정: 평균 **16.6ms**, p95 **16.7ms**, 최대 **16.8ms**, 33ms 초과 **0회**
- 팬/줌 중 60fps 유지, 77ms 롱태스크 1회(응답 처리)
- 최초 전체(all) 개요 로딩은 envelope **3.2s** + raw-sample **2.1s**로 지연이 있음
  - 차트는 계속 조작 가능하지만 첫 개요 표시까지 기다림
  - 다음 개선: 전체 개요도 롤업 기반으로 대체
- 팬 1회당 상세 요청 1회 발생 (약 80ms)
  - 디바운스/인접 구간 프리패치로 요청 횟수를 줄일 여지
